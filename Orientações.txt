## PRODUTO

O produto é um painel pessoal de acompanhamento de peso e composição corporal.

O objetivo é permitir acompanhar minha evolução corporal ao longo do tempo de forma visual, clara e agradável.

Implemente e preserve todas as funcionalidades existentes no projeto.

Preserve os cálculos existentes e suas regras de negócio.

O usuário deve poder:

- criar registros;
- visualizar registros;
- editar registros;
- excluir registros;
- acompanhar sua evolução;
- consultar históricos e métricas existentes no projeto.

Não altere cálculos ou regras de negócio existentes sem justificar a alteração.

==================================================
AUTENTICAÇÃO
==================================================

Os dados devem ficar persistidos no Supabase e sincronizados entre meus dispositivos.

Embora seja um produto de uso exclusivamente pessoal, implemente uma autenticação mínima e sem atrito utilizando exclusivamente Magic Link por e-mail.

O objetivo da autenticação é apenas:

1. identificar o usuário;
2. proteger os dados no Supabase;
3. permitir sincronização segura entre dispositivos.

O fluxo deve:

- não utilizar senha;
- não exigir cadastro tradicional;
- não criar sistema de perfis;
- não criar avatar;
- não criar sistema de equipes;
- não criar organizações;
- utilizar o `auth.uid()` do Supabase para identificar o proprietário dos dados;
- proteger as rotas que exigem autenticação.

NÃO crie:

- sistema de perfis;
- assinaturas;
- planos;
- equipes;
- organizações;
- permissões administrativas;
- funcionalidades comerciais;
- sistema de convite;
- sistema de cobrança;
- qualquer outra funcionalidade típica de SaaS que não seja necessária para este produto pessoal.

==================================================
SUPABASE
==================================================

Utilize o Supabase como banco de dados principal.

Crie toda a estrutura necessária para persistência dos dados, incluindo:

- tabelas;
- colunas;
- tipos;
- relacionamentos;
- índices;
- constraints;
- políticas de Row Level Security.

As políticas de RLS devem garantir que um usuário autenticado só consiga:

- consultar seus próprios registros;
- criar seus próprios registros;
- editar seus próprios registros;
- excluir seus próprios registros.

Não confie apenas na interface para segurança.

A segurança deve ser garantida no nível do banco de dados.

Não exponha secrets, service role keys ou qualquer chave privada no frontend.

Utilize somente as variáveis públicas apropriadas no cliente.
